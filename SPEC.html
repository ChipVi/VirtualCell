0The problem the challenge poses

The Arc Institute's Virtual Cell Challenge asks for a model that predicts how a cell's transcriptome changes after one gene is switched off. The data are a Perturb-seq screen: H1 human embryonic stem cells receive a guide RNA that silences one target gene by CRISPRi, and each cell is then profiled with single-cell RNA sequencing.

GivenTraining cells (raw UMI counts over ~18k genes) labelled with their target gene or non-targeting control, plus a list of new target genes and how many cells to produce for each.
WantedAn .h5ad file with synthetic cells for every new target gene (and the control cells).
Scored byThree metrics computed against real held-out cells: MAE, Perturbation Discrimination Score (PDS), Differential Expression Score (DES). See step 8.

The hard part is that the scored target genes were never knocked down in training. A model must therefore reason from what it knows about the gene (its expression pattern, its protein) to what silencing it will do.

Plain PyTorch plus the standard single-cell stack. No GPU is required for the demo.

2Data: the challenge format and a synthetic stand-in

The real training file is several gigabytes, so the project ships a simulator that writes the same files with the same schema. Everything downstream works unchanged on the real data.

FileContent
adata_Training.h5adcells × genes matrix of raw counts; obs.target_gene (gene symbol or non-targeting), obs.batch
pert_counts_Validation.csvtarget_gene, n_cells, median_umi_per_cell: what to generate
gene_names.csvthe gene order every submission must follow
adata_Validation.h5adreal cells for the held-out targets. Only the simulator produces this; it exists so you can score locally.

How the simulator encodes biology (vcc_cpa/simulate.py)

  1. Genes are grouped into co-expression modules with a sparse low-rank factor model. Each cell has a random position in factor space, which produces realistic cell-to-cell variation.
  2. Knocking down a gene lowers its own expression by roughly 86 percent and shifts the modules it belongs to, so genes that co-vary with the target also respond. This is a stand-in for regulatory and pathway effects.
  3. Two sequencing runs add a small gene-wise offset (a batch effect), and each cell has its own library size.
  4. Counts are sampled from a negative binomial, matching the overdispersion of droplet sequencing.
  5. Perturbations, not cells, are split into train, validation and test, exactly like the challenge.

3Preprocessing (vcc_cpa/data.py)

  1. Read the file, keep the matrix sparse, cast labels to strings.
  2. Normalise each cell to 10,000 counts and apply log1p. This removes library-size differences and compresses the heavy right tail of count data. The same transform is applied at prediction and evaluation time.
  3. Encode target_gene as an integer with the control at index 0, and batch as an integer.
  4. Iterate minibatches by slicing the sparse matrix, so only one minibatch is ever dense. This is what lets the real 200k-cell file train on a laptop.

4Gene features: how the model handles genes it never saw (vcc_cpa/gene_features.py)

Vanilla CPA gives every perturbation a free, learned embedding. That is useless for a new gene. The project instead computes the perturbation embedding from a feature vector describing the gene:

PertEmb(gene) = MLP( feature(gene) )

  • Default, no download: PCA loadings. Run PCA on control cells and take each gene's loading on the top 50 components, standardised. Genes in the same co-expression module get similar vectors, and in the simulator, co-expression is exactly what determines the knockdown response. On real data this captures the gene's expression programme (cell-cycle, pluripotency, metabolism, and so on).
  • Optional: an external table. Pass --gene-features path.csv with one row per gene, for example ESM2 protein embeddings or Gene Ontology vectors. This is the route most challenge entries took.

Genes missing from the table receive a zero vector and a warning; their prediction then collapses to the control state, which is the safest fallback.

5The CPA model (vcc_cpa/model.py)

CPA (Lotfollahi et al., Mol Syst Biol 2023) is an autoencoder whose latent space is additive: a cell's representation is the sum of a perturbation-free basal state, a perturbation term and covariate terms.

BlockShapeRole
Encodergenes → 256 → 256 → 64Maps a cell to its basal latent vector.
PertEmbfeature dim → 128 → 64Latent shift caused by knocking down the target. Zero for control cells.
BatchEmblookup, 64Latent shift explained by the sequencing batch.
Decoder64 → 256 → 256 → genesBack to log-normalised expression. Trained with mean squared error.
Adversaries64 → 128 → classesClassifiers used only for disentanglement; discarded after training.

Why additive? Because it makes the counterfactual trivial: take a control cell's z_basal, add the embedding of a gene that was never seen, decode. The whole challenge submission is that one line.

6Training (vcc_cpa/train.py)

  1. Hold out unseen genes. 15 percent of training perturbations are removed entirely. They are the internal proxy for the challenge's hidden targets and drive checkpoint selection.
  2. Alternate two optimisers (the CPA recipe). Every third step updates the adversaries so they get better at reading perturbation and batch out of a frozen z_basal. The other steps update encoder, decoder and embeddings with loss = MSE(x̂, x) − λ · (CE_pert + CE_batch), which rewards a z_basal the adversaries cannot classify. λ defaults to 0.05; gradients are clipped for stability.
  3. After every epoch, predict each held-out perturbation from 500 random control cells and report the pseudobulk MAE and the Pearson correlation between predicted and true expression deltas (change relative to control). The checkpoint with the lowest held-out MAE is saved together with gene names, batch names and the gene-feature matrix, so prediction is self-contained.
The reconstruction term alone would let z_basal memorise the perturbation, and the decoder would then ignore PertEmb. The adversarial term is what forces the perturbation effect into the embedding, where it can be transferred to new genes.

7Prediction and submission (vcc_cpa/predict.py)

  1. Load the checkpoint and the training file, keep only the non-targeting cells: they are the biological "before" state.
  2. For each row of pert_counts_Validation.csv, sample n_cells control cells (with replacement if needed), encode them, add PertEmb(feature(target_gene)) and the cell's own batch embedding, decode. Because each control cell has its own z_basal, the pseudo-cells inherit realistic cell-to-cell variability.
  3. Residual trick (default). Instead of returning the decoded cell, return x_control + [decode(z + shift) − decode(z)]. The decoder's reconstruction error appears in both terms and cancels, so only the predicted change is applied to the real cell. --no-residual gives the original CPA behaviour; --baseline skips the model and relabels control cells, the "no change" reference every submission must beat.
  4. Convert back to counts: expm1(x̂) / 10,000 × median_umi_per_cell, rounded and clipped at zero. The official cell-eval prep tool then re-normalises consistently.
  5. Append real control cells (the submission must contain them) and write an .h5ad with obs.target_gene and the gene order of the model.
cell-eval prep -i outputs/vcc/prediction.h5ad -g data/gene_names.csv   # packages the .vcc file to upload

8Evaluation (vcc_cpa/evaluate.py)

Local re-implementations of the three challenge metrics, computed between the predicted file and real held-out cells. They are close to, but not literally, Arc's cell-eval code, so use them to compare your own runs, not to predict leaderboard numbers.

MetricHow it is computed hereReads as
MAEMean absolute difference between predicted and true pseudobulk (per-gene mean of log-normalised expression), averaged over perturbations.lower is better
PDSFor each perturbation, L1 distance from its predicted pseudobulk to every true pseudobulk; rank of the correct one; score = 1 − rank/N.1 = perfect, about 0.5 = random
DESDifferential expression vs control with a Wilcoxon rank-sum test and Benjamini–Hochberg correction on both true and predicted cells; overlap of the true DE set with the top-k predicted DE genes (k = true set size), divided by k.1 = perfect, 0 = no overlap
Pearson ΔCorrelation of predicted vs true expression change relative to control. Not a challenge metric, but the most intuitive diagnostic.1 = perfect direction

The script writes scores.csv (one row per perturbation, including how many DE genes each really has) and scores.json with the averages.

Measured on the synthetic demo (12 unseen target genes, seed 0, 20 epochs)

PredictionMAE ↓PDS ↑DES ↑Pearson Δ ↑

MAE alone is a poor guide: "predict no change" scores well on it because most genes do not respond to any single knockdown. PDS and DES are the metrics that reward actually knowing what a knockdown does; the baseline collapses to random on PDS and to zero on DES. This is exactly why the challenge uses three metrics.

9Run it

# one command, synthetic data, about a minute on CPU
.venv\Scripts\python.exe -m vcc_cpa.pipeline

# or step by step
.venv\Scripts\python.exe -m vcc_cpa.simulate --out data
.venv\Scripts\python.exe -m vcc_cpa.train    --data data/adata_Training.h5ad --out outputs/run1
.venv\Scripts\python.exe -m vcc_cpa.predict  --model outputs/run1/model.pt --data data/adata_Training.h5ad \
                                            --pert-counts data/pert_counts_Validation.csv --out outputs/run1/prediction.h5ad
.venv\Scripts\python.exe -m vcc_cpa.evaluate --pred outputs/run1/prediction.h5ad --truth data/adata_Validation.h5ad \
                                            --control data/adata_Training.h5ad
.venv\Scripts\python.exe -m pytest -q          # end-to-end smoke test on a tiny screen

# reference score: relabelled control cells ("no change"), then evaluate the same way
.venv\Scripts\python.exe -m vcc_cpa.predict  --model outputs/run1/model.pt --data data/adata_Training.h5ad \
                                            --pert-counts data/pert_counts_Validation.csv --out outputs/run1/baseline.h5ad --baseline

Swap data/ for the real challenge files and the same commands train and produce a submission. Use --gene-features to plug in ESM2 or other gene embeddings.

10Known limitations and sensible next steps

  • Gaussian output. The decoder minimises MSE on log-normalised values. The original CPA fits a Gaussian with learned variance, and count models (negative binomial) are more faithful to UMI data.
  • Gene features decide everything. PCA loadings know nothing about a gene that is barely expressed in control cells. Protein-language-model embeddings (ESM2) or knowledge-graph features generalise better.
  • Pseudo-cells are decoded controls. They cannot express variability that is specific to the perturbed state, which limits DES on perturbations with strong, heterogeneous effects.
  • Small demo scale. Defaults (2,000 genes, 80 perturbations) are chosen to run in a minute; raise --epochs, --latent and --hidden for real data.
  • Local metrics approximate cell-eval. Always run the official package before trusting a number.

Biology panel

Click a blue term in the text to jump here, or filter.

CRISPRi
CRISPR interference: a catalytically dead Cas9 fused to a repressor (KRAB) is parked on a gene's promoter and blocks transcription. The DNA is not cut, so the gene is turned down (knockdown), not deleted (knockout).
guide RNA (sgRNA)
The short RNA that tells dCas9 which gene to sit on. One guide = one target gene; the guide's sequence is read out from the cell's RNA to label each cell with its perturbation.
H1 hESC
A widely used human embryonic stem cell line. Pluripotent, so the same knockdown can also be studied in cells that later differentiate. The challenge data are all H1 cells.
Perturb-seq
Pooled CRISPR screen plus single-cell RNA-seq. Thousands of cells each carry one guide; sequencing recovers both the guide identity and the full transcriptome per cell.
Transcriptome
The set of all mRNA molecules in a cell and their abundances. Here: a vector of ~18,000 gene expression values per cell.
scRNA-seq
Single-cell RNA sequencing. Cells are captured in droplets, their mRNAs barcoded per cell and sequenced, giving one expression profile per cell rather than an average over tissue.
UMI count
Unique Molecular Identifier: a random tag on each captured mRNA molecule so PCR duplicates are counted once. The raw data matrix holds integer UMI counts per gene per cell.
Target gene / perturbation
The gene a guide silences. "Perturbation" is the generic term for any experimental treatment; in this challenge every perturbation is a single-gene CRISPRi knockdown.
Non-targeting control (NTC)
Cells that received a guide with no matching sequence in the genome. They experience the same handling but no knockdown, so they define the baseline every effect is measured against.
Batch effect
Technical variation between experimental runs (different day, chip, reagent lot) that shifts expression for reasons unrelated to biology. The model gets an explicit batch embedding so this does not masquerade as a perturbation effect.
Library size
Total UMI counts in a cell. It varies several-fold between cells purely from capture efficiency, which is why counts are normalised per cell first.
CP10k + log1p
Scale each cell so its counts sum to 10,000 (counts per 10k), then take log(1 + x). Standard single-cell normalisation; it makes values comparable across cells and roughly Gaussian.
Negative binomial
The count distribution that fits UMI data: a Poisson whose rate itself varies between cells (overdispersion). Variance grows faster than the mean, unlike a plain Poisson.
Co-expression module
A group of genes whose expression rises and falls together across cells, usually because they sit in the same pathway or are controlled by the same transcription factors. Knocking down one member tends to move the whole module.
Pseudobulk
Average expression profile of all cells sharing a label (e.g. one perturbation). Reduces single-cell noise; most challenge metrics compare pseudobulks.
Differential expression (DE)
Genes whose expression differs significantly between two groups, here perturbed vs control cells. The DE gene set is the biological "fingerprint" of a knockdown.
Wilcoxon rank-sum test
Non-parametric test (also called Mann–Whitney U) asking whether values in one group tend to be larger than in another. Robust to the skewed, zero-heavy distributions of single-cell data.
Benjamini–Hochberg / FDR
Testing 18,000 genes at once produces many false positives by chance. BH adjustment controls the false discovery rate so that, say, at most 5 percent of the called DE genes are expected to be false.
Latent space
The low-dimensional vector (64 numbers here) an autoencoder compresses a cell into. Distances in it reflect similarity of cell state.
Basal state
CPA's term for the part of a cell's latent vector that remains after perturbation and batch effects are subtracted: the cell's intrinsic identity, cell-cycle phase, and so on.
Disentanglement / adversary
Training trick that keeps perturbation information out of the basal state. A classifier tries to guess the perturbation from z_basal; the encoder is penalised whenever it succeeds, so perturbation effects are pushed into the separate perturbation embedding.
Counterfactual prediction
"What would this exact control cell look like if gene X were knocked down?" CPA answers by editing the latent vector and decoding, which is how unseen perturbations are predicted.
ESM2 embedding
A vector describing a protein, produced by a protein language model trained on millions of sequences. Genes with similar protein domains get similar vectors, giving the model a prior about genes never perturbed in training.
AnnData / .h5ad
The standard Python container for single-cell data: a cells × genes matrix (X), per-cell metadata (obs) and per-gene metadata (var), saved as HDF5.
